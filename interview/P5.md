## 5.1. HTTP Methods & REST

> **REST (Representational State Transfer)** là một bộ quy tắc kiến trúc thiết kế web service thao tác trên các Resource (tài nguyên) qua các phương thức HTTP:
>
> - `GET`: Lấy tài nguyên (Read).
> - `POST`: Tạo mới tài nguyên (Create).
> - `PUT`: Cập nhật/Thay thế hoàn toàn tài nguyên (Update).
> - `PATCH`: Cập nhật một phần của tài nguyên.
> - `DELETE`: Xóa tài nguyên (Delete).

## 5.2. HTTP Status Code

> Mã trạng thái trả về để báo cho Client biết kết quả xử lý:
>
> - **2xx (Thành công)**: `200 OK` (Thành công chung), `201 Created` (Tạo mới thành công, thường dùng cho POST).
> - **4xx (Lỗi Client)**: `400 Bad Request` (Gửi sai param/JSON), `401 Unauthorized` (Chưa đăng nhập/sai token), `403 Forbidden` (Đã đăng nhập nhưng cấm vào), `404 Not Found` (Sai URL).
> - **5xx (Lỗi Server)**: `500 Internal Server Error` (Bug code backend quăng Exception).

## 5.3. Stateless (Phi trạng thái)

> **Định nghĩa**: Server KHÔNG lưu giữ bất kỳ trạng thái (session) nào của Client giữa các request.
> **Ý nghĩa**: Giúp backend dễ dàng mở rộng (Scale-out) thành nhiều máy chủ ngang hàng, vì không cần đồng bộ Session. Client phải gửi kèm "thông tin nhận diện" (ví dụ **JWT Token**) trong MỌI request.

```http
# Client phải tự nhét JWT vào Header mỗi lần gọi API
GET /api/orders HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOiJIUzI1Ni...
```

## 5.4. Idempotent (Lũy đẳng)

> **Định nghĩa**: Bạn thực hiện cùng một HTTP Request **1 lần hay 100 lần** liên tiếp thì trạng thái (state) dữ liệu ở server vẫn y hệt nhau, không có side-effect ngoài ý muốn.
>
> - **Idempotent methods**: `GET` (đọc chục lần vẫn thế), `PUT` (sửa id=1 thành "A" mười lần thì kết quả vẫn là "A"), `DELETE` (xóa id=1 chục lần thì nó vẫn mất rồi).
> - **NON-idempotent**: `POST` (Bấm gửi thanh toán bị lag 10 lần -> Server tạo ra 10 hóa đơn mới, mất tiền 10 lần).

```java
// Idempotent: An toàn khi retry (F5)
@PutMapping("/{id}")
public User update(@PathVariable Long id, @RequestBody UserDTO dto) { ... }

// Non-idempotent: Không an toàn khi retry, cần xử lý chặn double-click ở front-end
@PostMapping
public User create(@RequestBody UserDTO dto) { ... }
```

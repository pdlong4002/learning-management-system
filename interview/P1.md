## 1. Bốn tính chất OOP

### 1.1 Đóng gói (Encapsulation)

> **Đóng gói** là nguyên lý che giấu trạng thái nội bộ (state) của object bằng access modifier (`private`), và chỉ cho phép truy cập/thay đổi thông qua các method công khai (getter/setter) có kiểm soát (validate).
> **Lợi ích**: Đảm bảo dữ liệu luôn ở trạng thái hợp lệ (data integrity), mọi thay đổi đi qua một điểm kiểm soát duy nhất giúp dễ debug và bảo trì.

```java
public class TaiKhoan {
    private double soDu; // ẩn field, không cho truy cập trực tiếp

    public void napTien(double tien) {
        if (tien <= 0) throw new IllegalArgumentException("Số tiền không hợp lệ");
        soDu += tien;
    }
}
```

### 1.2 Kế thừa (Inheritance)

> **Kế thừa** cho phép một class (subclass) tái sử dụng field và method từ một class khác (superclass), thể hiện quan hệ "is-a".
> **Lợi ích**: Tái sử dụng code và xây dựng cấu trúc phân cấp (hierarchy) hợp lý. Java chỉ hỗ trợ single inheritance đối với class để tránh Diamond Problem.

```java
class NhanVien { protected double luongCoBan = 1000; }
class Developer extends NhanVien {
    public double tinhLuong() { return luongCoBan + 500; } // Tái sử dụng luongCoBan
}
```

### 1.3 Đa hình (Polymorphism)

> **Đa hình** là khả năng cùng một phương thức nhưng hành vi thực thi phụ thuộc vào kiểu đối tượng thực tế tại runtime (runtime polymorphism, đạt được qua method overriding).
> **Lợi ích**: Giúp code linh hoạt, dễ mở rộng (tuân thủ Open/Closed principle).

```java
abstract class HinhHoc { abstract void ve(); }
class HinhTron extends HinhHoc { void ve() { System.out.println("Vẽ tròn"); } }

HinhHoc h = new HinhTron();
h.ve(); // Đa hình: Gọi hàm của HinhTron lúc runtime
```

### 1.4 Trừu tượng (Abstraction)

> **Trừu tượng** là nguyên lý chỉ expose ra những gì cần thiết cho bên sử dụng (WHAT), ẩn đi toàn bộ chi tiết cài đặt phức tạp bên trong (HOW).
> **Lợi ích**: Giảm thiểu sự phức tạp khi sử dụng API, loose coupling.

```java
public interface PaymentGateway {
    void process(double amount); // Chỉ biết tính năng xử lý thanh toán, giấu chi tiết call API
}
```

## 2. Interface vs Abstract Class

> - **Abstract class** biểu diễn quan hệ **is-a**, dùng khi các class con có chung bản chất, có thể chia sẻ state (field) và concrete method.
> - **Interface** biểu diễn quan hệ **can-do**, dùng khi các class không liên quan nhưng cùng chung hành vi. Không thể giữ state (chỉ có public static final field).
>   **Lợi ích**: Interface giúp vượt qua giới hạn đa kế thừa của Java.

```java
abstract class DongVat { 
    int tuoi; // Abstract class có state
    abstract void keu(); 
}
interface Bay { 
    void bay(); // Interface thuần túy định nghĩa hành vi
}
```

## 3. Object (equals, hashCode)

> Mọi class trong Java đều kế thừa từ `java.lang.Object`.
>
> - `equals()`: Mặc định so sánh địa chỉ ô nhớ (`==`). Phải override để so sánh giá trị logic.
> - `hashCode()`: Trả về mã băm.
>   **Quy tắc (Contract) quan trọng**: Nếu 2 object `equals()` nhau thì `hashCode()` bắt buộc phải giống nhau. Nếu không, khi bỏ vào `HashMap` / `HashSet` sẽ bị lỗi không tìm thấy (do tìm sai bucket).

```java
public class User {
    private String cmnd;
  
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return Objects.equals(cmnd, user.cmnd); // So sánh logic bằng CMND
    }

    @Override
    public int hashCode() {
        return Objects.hash(cmnd);
    }
}
```

## 4. String vs StringBuilder

> - `String` là **immutable** (bất biến) và thread-safe. Mỗi khi nối chuỗi sẽ tạo ra object mới, rất tốn memory.
> - `StringBuilder` là **mutable**, thao tác trực tiếp trên mảng char nội bộ. Chạy cực nhanh khi nối chuỗi nhiều lần trong vòng lặp nhưng KHÔNG thread-safe.

```java
// BAD: Sinh ra 1000 object String rác
String s = ""; 
for(int i=0; i<1000; i++) s += i; 

// GOOD: Sửa trực tiếp trên 1 object duy nhất
StringBuilder sb = new StringBuilder();
for(int i=0; i<1000; i++) sb.append(i);
```

## 5. Exception

> - **Checked Exception** (kế thừa `Exception`): Lỗi bắt buộc phải xử lý lúc biên dịch (dùng `try-catch` hoặc `throws`). VD: `IOException`.
> - **Unchecked Exception** (kế thừa `RuntimeException`): Lỗi logic lúc runtime, không bắt buộc xử lý code, tự ném ra làm chết chương trình. VD: `NullPointerException`.
>   **Ý nghĩa**: Giúp phân tách rõ lỗi hạ tầng hệ thống (bắt buộc dev phải phòng hờ) và lỗi do dev code ngu (cần sửa code chứ không catch).

```java
public void docFile() throws IOException {
    // Phải khai báo throws vì FileReader ném ra Checked Exception
    FileReader fr = new FileReader("test.txt"); 
}
```

## 6. Collections Framework

> - **List**: Có thứ tự, cho phép trùng lặp, truy cập theo index (ArrayList nhanh khi get, LinkedList nhanh khi insert/delete).
> - **Set**: Không trùng lặp. Đảm bảo tính duy nhất qua `equals()` và `hashCode()`.
> - **Map**: Lưu theo cặp Key-Value. Key không trùng.

```java
List<String> list = new ArrayList<>(); // Truy cập O(1)
Set<String> set = new HashSet<>();     // Check tồn tại O(1)
Map<String, User> map = new HashMap<>(); // Tra cứu theo ID O(1)
```

## 7. Generics

> **Generics** cho phép tham số hóa kiểu dữ liệu, giúp ép kiểu an toàn ngay lúc biên dịch (compile-time type safety) và tái sử dụng code cho nhiều kiểu dữ liệu khác nhau.
> **Lợi ích**: Tránh lỗi `ClassCastException` lúc chạy, không cần ép kiểu thủ công.

```java
// Không dùng Generics: Bị ép kiểu thủ công, rủi ro Runtime
List list = new ArrayList();
list.add("Hello");
Integer i = (Integer) list.get(0); // Lỗi ClassCastException

// Dùng Generics: An toàn
List<String> listGen = new ArrayList<>();
// listGen.add(1); // Lỗi Compile ngay lập tức
```

## 8. Stream API & 9. Lambda

> - **Lambda**: Cú pháp ngắn gọn thay thế cho Anonymous Class khi làm việc với Functional Interface.
> - **Stream API**: Xử lý Collection theo hướng khai báo (Declarative). Hỗ trợ pipelining (nối nhiều thao tác) và thi hành lười (Lazy Evaluation).
>   **Lợi ích**: Code sạch, dễ đọc, dễ viết thao tác Map-Reduce, hỗ trợ chạy song song `parallelStream()`.

```java
List<Integer> numbers = Arrays.asList(1, 2, 3, 4, 5);

// Dùng Lambda & Stream để lọc số chẵn và nhân đôi
List<Integer> result = numbers.stream()
    .filter(n -> n % 2 == 0) // Lambda
    .map(n -> n * 2)         // Lambda
    .collect(Collectors.toList());
```

## 10. Optional

> `Optional<T>` là một wrapper class biểu diễn giá trị có thể null hoặc không.
> **Lợi ích**: Ép lập trình viên phải tường minh xử lý trường hợp null, giảm triệt để lỗi `NullPointerException`.

```java
Optional<String> name = Optional.ofNullable(getUserName());

// Xử lý thanh lịch không cần check if(name != null)
String res = name.orElse("Khách"); 

// Chạy logic an toàn
name.ifPresent(n -> System.out.println("Xin chào " + n));
```

## 11. Concurrency (Thread, Synchronized, Pool)

> - **Thread vs Runnable**: Nên implement `Runnable` để tách biệt logic task và luồng thực thi, dễ nhét vào ThreadPool.
> - **Synchronized**: Đảm bảo 1 thời điểm chỉ 1 thread chạy vào vùng critical section, tránh **Race Condition**.
> - **ThreadPool (ExecutorService)**: Khởi tạo sẵn 1 pool các thread. Tái sử dụng thread thay vì tạo mới/hủy liên tục, giúp chống cạn kiệt bộ nhớ và CPU.

```java
ExecutorService pool = Executors.newFixedThreadPool(10);
pool.submit(() -> {
    // Công việc chạy đa luồng
    System.out.println(Thread.currentThread().getName());
});
```

## 12. JVM (Heap, Stack, GC)

> - **Stack**: Mỗi thread có 1 stack riêng. Lưu biến primitive (int, double) và các frame gọi hàm (LIFO).
> - **Heap**: Dùng chung cho toàn ứng dụng. Nơi chứa mọi Object được `new` ra.
> - **Garbage Collection (GC)**: Tiến trình tự động dọn dẹp các Object trên Heap không còn ai reference tới (Unreachable). Giúp dev Java không phải tự free memory như C/C++.

```java
public void test() {
    int age = 20; // age lưu ở Stack
    User u = new User(); // u lưu ở Stack, trỏ tới Object User nằm trên Heap
} // Hàm kết thúc: age và u tự hủy khỏi Stack. Object User ở Heap chờ GC dọn.
```

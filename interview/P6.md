# PHẦN VI — Security

Bộ câu trả lời theo format: **Định nghĩa chuẩn → Ý nghĩa/Lợi ích → Ví dụ minh họa (code)**.

---

## 6.1. Authentication vs Authorization

> - **Authentication (Xác thực)**: Trả lời câu hỏi *"Bạn là ai?"* (VD: Đăng nhập bằng username/password, OTP, OAuth2).
> - **Authorization (Phân quyền)**: Trả lời câu hỏi *"Bạn được phép làm gì?"* (VD: User thường chỉ được xem, Admin mới được xóa bài).

```java
// Authentication: Filter chặn request, kiểm tra token có hợp lệ không (có phải là user của hệ thống không)
// Authorization: Phân quyền ở Controller, chỉ ROLE_ADMIN mới vào được
@PreAuthorize("hasRole('ADMIN')")
@DeleteMapping("/{id}")
public void deleteCourse(@PathVariable Long id) { ... }
```

## 6.2. JWT (JSON Web Token)

> **JWT** là một chuỗi mã hóa gồm 3 phần (Header, Payload, Signature) dùng để xác thực client trong mô hình Stateless.
> **Lợi ích**: Server không cần lưu Session dưới DB hay RAM (vì mọi thông tin cần thiết như user_id, role đã nằm trong Payload của JWT và được bảo vệ bằng Signature). Rất hợp cho hệ thống Microservices.

```java
// Cấu trúc của JWT: xxxxx.yyyyy.zzzzz
// Payload có thể giải mã dễ dàng (Base64), KHÔNG được chứa mật khẩu trong Payload.
// Signature = HMAC(Header + Payload, SecretKey). Nếu ai đó sửa Payload, Signature sẽ sai và server từ chối.
```

## 6.3. BCrypt

> **BCrypt** là thuật toán băm (hashing) mật khẩu một chiều.
> **Lợi ích**: Không thể dịch ngược từ mã băm ra mật khẩu gốc. BCrypt tự động sinh ra một chuỗi ngẫu nhiên (Salt) trộn vào mật khẩu trước khi băm, giúp chống lại tấn công Rainbow Table (hai người đặt trùng mật khẩu "123456" nhưng mã băm ra vẫn khác nhau hoàn toàn).

```java
// Spring Security hỗ trợ sẵn BCrypt
PasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("123456"); 
boolean isMatch = encoder.matches("123456", hash); // true
```

## 6.4. CORS (Cross-Origin Resource Sharing)

> **CORS** là cơ chế bảo mật của TRÌNH DUYỆT (Browser). Trình duyệt mặc định sẽ chặn các lời gọi API từ domain này (VD: `localhost:3000` của React) sang domain khác (VD: `localhost:8080` của Spring Boot) nếu server không cho phép.
> **Cách xử lý**: Config Backend gửi kèm Header `Access-Control-Allow-Origin` để cho phép domain của frontend gọi tới.

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**") // Áp dụng cho mọi API
                .allowedOrigins("http://localhost:3000") // Chỉ cho phép React gọi
                .allowedMethods("GET", "POST", "PUT", "DELETE");
    }
}
```

## 6.5. CSRF (Cross-Site Request Forgery)

> **CSRF** là tấn công giả mạo request. Hacker lừa người dùng click vào 1 link xấu (VD: `nganhang.com/chuyen-tien?den=Hacker`), nếu người dùng đang đăng nhập (trình duyệt tự động đính kèm Session Cookie), tiền sẽ bị chuyển mất.
> **Cách xử lý**:
>
> - Nếu dùng **Session/Cookie**: Phải bật CSRF token (Spring Security làm tự động).
> - Nếu dùng **JWT (Stateless)**: Client chủ động nhét JWT vào Header thay vì dùng Cookie -> Thường sẽ `csrf.disable()` trong cấu hình Spring Security vì trình duyệt không tự động gửi Header.

```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    // Tắt CSRF vì hệ thống dùng JWT Stateless, không dùng Cookie
    http.csrf(AbstractHttpConfigurer::disable); 
    // ...
}
```

## 3.1. Entity & Entity Lifecycle

> **Entity** là class Java đóng vai trò ánh xạ (ORM - Object Relational Mapping) thành 1 bảng trong Database.
> **Lifecycle** có 4 trạng thái:
>
> 1. **Transient**: Vừa `new` ra, chưa dính dáng gì tới Hibernate.
> 2. **Managed / Persistent**: Đã đưa cho EntityManager quản lý (bằng `persist()` hoặc `findById()`). Mọi thay đổi trên object sẽ tự động update DB.
> 3. **Detached**: Bị đẩy ra khỏi sự quản lý của Hibernate (vd: sau khi đóng session hoặc gọi `clear()`). Sửa object lúc này sẽ KHÔNG update DB.
> 4. **Removed**: Đánh dấu để chờ xóa khỏi DB.

## 3.2. Persistence Context & Dirty Checking

> **Persistence Context** là bộ đệm (First-level Cache) nằm giữa ứng dụng và Database, nơi chứa các Entity đang ở trạng thái Managed.
> **Dirty Checking**: Tính năng tự động kiểm tra xem Entity trong Persistence Context có bị thay đổi (dirty) hay không so với lúc ban đầu. Nếu có, Hibernate tự động sinh câu lệnh `UPDATE` khi transaction commit mà không cần bạn phải gọi lệnh `save()`.

```java
@Transactional
public void updateName(Long id, String newName) {
    // 1. Kéo Entity vào Persistence Context (trạng thái Managed)
    User user = userRepository.findById(id).get(); 
  
    // 2. Chỉ cần set lại giá trị
    user.setName(newName); 
  
    // Hết hàm (Commit Transaction) -> Dirty Checking phát hiện thay đổi 
    // -> TỰ ĐỘNG chạy câu UPDATE xuống DB. Không cần gọi userRepository.save(user)!
}
```

## 3.3. FetchType & Cascade

> - **FetchType.LAZY**: Không query dữ liệu con ngay, chỉ query khi thực sự gọi hàm `get()`. Giúp tiết kiệm RAM và CPU. Luôn ưu tiên dùng.
> - **FetchType.EAGER**: Kéo toàn bộ dữ liệu con lên bộ nhớ ngay lập tức. Rất dễ gây phình bộ nhớ và chạy chậm.
> - **Cascade**: Cấu hình hiệu ứng "dây chuyền". VD `CascadeType.ALL`: khi `persist`, `remove` entity cha thì tự động áp dụng lên các entity con của nó.

```java
@Entity
public class Category {
    // Nếu xóa Category, tất cả Product con cũng bị xóa theo. 
    // Dữ liệu con chỉ load khi gọi getProducts() (LAZY).
    @OneToMany(mappedBy = "category", fetch = FetchType.LAZY, cascade = CascadeType.ALL)
    private List<Product> products;
}
```

## 3.4. N+1 Problem, JOIN FETCH, @EntityGraph

> **N+1 Problem**: Là lỗi khi dùng LAZY fetch. 1 câu query lấy N bản ghi cha. Sau đó lập qua list cha, gọi `.getCon()` thì sinh ra N câu query lẻ nữa -> Tổng cộng có N+1 query. Làm hệ thống bị chậm cực kỳ nghiêm trọng.

```java
// CÁCH FIX 1: Dùng JOIN FETCH trong JPQL. Bắt nó nối bảng query luôn 1 lần.
@Query("SELECT c FROM Category c JOIN FETCH c.products")
List<Category> findAllWithProducts();

// CÁCH FIX 2: Dùng @EntityGraph. Dễ viết hơn, cho phép ghi đè thuộc tính LAZY thành EAGER lúc runtime.
@EntityGraph(attributePaths = {"products"})
@Query("SELECT c FROM Category c")
List<Category> findAllWithProductsGraph();
```

## 3.5. Transaction

> **Transaction** đảm bảo một nhóm các thao tác DB chạy theo nguyên lý ACID (Thành công toàn bộ hoặc thất bại toàn bộ). Trong Spring Boot, chỉ cần dùng `@Transactional`. Mặc định Spring sẽ **Rollback (hoàn tác)** nếu có `RuntimeException` hoặc `Error` ném ra.

```java
@Transactional // Nếu lỗi, mọi lệnh insert/update trong này bị hủy hết
public void checkout(Order order) {
    orderRepo.save(order);
    paymentRepo.deductMoney();
    if(true) throw new RuntimeException("Lỗi hệ thống"); // Sẽ ROLLBACK 2 lệnh trên
}
```

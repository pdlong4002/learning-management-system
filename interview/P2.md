## 2.1. Spring vs Spring Boot

> **Spring Framework** là một hệ sinh thái khổng lồ cung cấp IoC/DI, MVC, Security, v.v., nhưng đòi hỏi cấu hình thủ công rất rườm rà (thường bằng XML). **Spring Boot** là một framework xây dựng trên nền Spring, cung cấp tính năng **auto-configuration** và nhúng sẵn web server (Tomcat/Undertow), giúp khởi tạo dự án nhanh chóng theo triết lý "Convention over Configuration".

```java
// Chỉ cần 1 annotation để kích hoạt toàn bộ sức mạnh Spring Boot
@SpringBootApplication 
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

## 2.2. IoC (Inversion of Control) & DI (Dependency Injection)

> - **IoC**: "Đảo ngược điều khiển" — thay vì object tự khởi tạo các dependency (`new Object()`), quyền điều khiển được giao cho **Spring Container**.
> - **DI**: Là cách triển khai IoC. Spring Container tự động tìm và "tiêm" các dependency cần thiết vào object tại thời điểm runtime.

```java
@Service
public class OrderService {
    private final PaymentService paymentService;

    // Constructor Injection (Best Practice): Spring tự tiêm PaymentService vào đây
    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

## 2.3. Bean & Bean Scope

> **Bean** là những object do Spring Container khởi tạo, cấu hình và quản lý vòng đời.
> **Bean Scope** quy định phạm vi tồn tại của Bean:
>
> - `singleton` (mặc định): 1 instance duy nhất trên toàn ApplicationContext. Dùng cho object không có trạng thái (Stateless - vd: Service, Repository).
> - `prototype`: Khởi tạo 1 instance mới mỗi lần được yêu cầu. Dùng cho object có trạng thái (Stateful).
> - `request`/`session`: (chỉ dùng trong web) Tồn tại trong phạm vi 1 HTTP Request hoặc Session.

```java
@Component
@Scope("prototype")
public class StatefulTask {
    // Sẽ được tạo mới liên tục khi inject
}
```

## 2.4. Bean Lifecycle

> Vòng đời của một Bean được Spring quản lý qua các bước:
>
> 1. **Instantiation**: Gọi constructor khởi tạo object.
> 2. **Populate Properties**: Inject các dependency (DI).
> 3. **Initialization**: Chạy hàm `@PostConstruct` hoặc `afterPropertiesSet()`.
> 4. **Ready for Use**: Trạng thái sẵn sàng hoạt động.
> 5. **Destruction**: Chạy hàm `@PreDestroy` hoặc `destroy()` khi ứng dụng tắt.

```java
@Component
public class MyBean {
    public MyBean() { System.out.println("1. Constructor"); }
  
    @PostConstruct
    public void init() { System.out.println("3. Init - Sau khi DI xong"); }
  
    @PreDestroy
    public void destroy() { System.out.println("5. Dọn dẹp trước khi tắt"); }
}
```

## 2.5. AOP (Aspect-Oriented Programming)

> Lập trình hướng khía cạnh. Cho phép tách các **cross-cutting concerns** (logic lặp lại không thuộc nghiệp vụ chính như Logging, Transaction, Security) ra khỏi business logic, bọc chúng lại thành các **Aspect** để áp dụng động vào code.

```java
@Aspect
@Component
public class LoggingAspect {
    // Chạy hàm này trước mọi hàm trong package service
    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore() {
        System.out.println("Đang gọi hàm service...");
    }
}
```

## 2.6. Spring MVC & Validation

> **Spring MVC** dùng mô hình Front Controller (DispatcherServlet) để hứng toàn bộ HTTP Request, map vào đúng `@Controller` xử lý, sau đó trả về dữ liệu (JSON/View).
> **Validation** kết hợp `@Valid` ở Controller và các Annotation (`@NotNull`, `@Size`) ở DTO để kiểm tra tính hợp lệ dữ liệu.

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @PostMapping
    public ResponseEntity<String> createUser(@Valid @RequestBody UserDTO dto) {
        return ResponseEntity.ok("User hợp lệ");
    }
}

class UserDTO {
    @NotBlank(message = "Tên không được bỏ trống")
    private String name;
}
```
